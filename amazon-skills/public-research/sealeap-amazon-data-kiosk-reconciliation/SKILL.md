# Data Kiosk 一方经营数据对账

用可复核的一方数据解释经营变化。先明确数据集与一行记录的含义，再拼接业务指标。

## 工作流

1. 固定 seller/vendor 身份、marketplace、币种、时区、日期口径、完整时间窗、指标与业务问题；按 [数据契约](references/data-contract.md) 建立字段字典。
2. 阅读 [官方基线](references/official-baseline.md)，查看当前 API/schema、授权角色及数据可用性。2026-09-30 发布的新数据集不代表所有历史日期、字段或账户都可查。
3. 保存实际 schema 版本/摘要及查询文本。只从真实字段构造 GraphQL；先小日期窗、小字段集试查，并核查查询额度、成本与授权。无权限或无对应数据时交付 UNKNOWN，不猜 query 字段。
4. 创建查询后记录 query ID，沿同一任务轮询终态并取得文档。失败时保存类型和响应；状态不明先查原 query，不另起重复任务。短效文档 URL 不写入公开输出。
5. 保存原始只读快照、行数、字段、时间、范围及文件哈希；把空值、未返回、被隐私阈值抑制和真实零分别标记。只允许在同数据集定义和相同粒度内聚合。
6. 按稳定键连接销售、费用、退款和退货。订单、件数、费用事件和退货件是不同粒度；先检查一对多关系和重复主键，不因 join 放大金额。
7. 与相同期间后台报表建立桥接：已匹配、时点差、范围差、缺失、无法解释。汇率与正负号显式记录；预测费用与实际入账分开。
8. 交付已对账指标和业务解释；存在决定性缺口则 HOLD。利润必须有成本、广告、退货等相应证据，不能把 net proceeds 称为净利润。

## 交付

schema/权限清单、查询与文档状态、原始文件索引、字段映射、唯一键审计、金额/计数对账和原因分类。每个指标关联来源、窗口、定义与证据编号；不上传业务明细到本 Skill 目录。
