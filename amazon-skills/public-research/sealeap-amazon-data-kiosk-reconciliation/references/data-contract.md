# 数据与对账契约

每份数据保存 dataset、schema_version、seller_id、marketplace_id、currency、timezone、date_basis、period_start、period_end、generated_at、query_id、document_sha256、row_grain、primary_key。

每个字段保存原名、含义、单位、正负号、Null 意义、是否可加、分子/分母和归因。请求字段与实际响应缺失字段分别保留。

## 对账步骤

先同币种同口径聚合原始金额，后重算率；使用十进制金额而非二进制浮点累加。差异 = 被核对总额 - 基准总额，容差由货币精度和任务明确指定。不得按差额强行生成费用项。

费用事件使用实际发生/入账日期；退款和原订单可在不同月。预估经济性数据与实际结算数据不能相加。退货原因频次不是全部销售的退货率；没有完整分母不计算该率。

## 典型验收

- 同一订单有两笔费用：费用表先按费用事件去重，按订单汇总后关联，订单销售额不得重复两遍。
- 一个日期未返回：覆盖不足，输出已观测小计，不宣称全月结果。
- 没有 COGS：可做费用/销售桥接，利润为 UNKNOWN。
- 新字段发布但查询拒绝：记录账户/schema 不支持，不改用来源不明的代理指标。
