# Seller Central 多渠道经营协同

先建立每个渠道的业务主键和库存责任，再试点同步。公开发布不能代替真实账号可用性。

## 工作流

1. 阅读 [官方基线](references/official-baseline.md)，确认美国站逐步开放状态、账户入口、支持的渠道与功能。逐项验证商品、库存、订单、价格、退款各能力，不以一个开关推断全覆盖。
2. 按 [同步契约](references/sync-contract.md) 建立渠道商品与内部 SKU 映射，核对变体、数量、套装、单位、税币种。相同名称不作主键；平台 listing ID 也不等于内部 SKU。
3. 记录每类数据的权威系统、写入方向、更新频率、延迟和冲突规则。价格和库存双向同步须有避免循环覆盖的机制；未知时仅只读对账。
4. 计算共享库存时区分可售、预留、在途、渠道安全库存和已接受未履约订单。不能把同一仓库库存按渠道各算一遍。
5. 核对渠道的履约、包装、追踪、取消、退款与配送承诺；按实际 MCF/3PL 费率计算成本。平台接入成功不证明渠道允许全部履约方式。
6. 为少量 SKU 建立批准范围内的试点：商品匹配、下单、库存占用、发货、追踪、取消及退款逐环节验收。无真实测试授权时只生成测试计划，不制造订单。
7. 用渠道+order_id+line_id 对账，记录同步事件 ID 与状态。写入超时先查目标订单与事件日志；无法消歧时停止，不重放可能已经成功的订单。
8. 比较准时率、超卖、异常单、费用与净贡献，达到约定阈值才扩大。撤销连接不等于撤销已接订单，退出计划须安排未完订单和库存责任。

## 交付

功能资格表、SKU 映射、库存与价格权威表、逐订单差异、试点验收、费用测算和退出方案。记录来源、时间与平台范围，不能把草稿称为已经接通。
